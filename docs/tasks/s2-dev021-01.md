## Acceptance criteria

- **DEV021-AC-01** Active vessel, mode and role are visible in the shell and the context region is a polite live region; values come only from the server response.
- **DEV021-AC-02** A switch to a granted vessel is verified by the server and audited (`WorkspaceRead/Success`, actor, tenant, target id).
- **DEV021-AC-03** Foreign-tenant, out-of-mode, withdrawn-grant and removed-membership targets are denied (404 / 401·403) without names, codes or role data; the denied target is attributable (`WorkspaceRead/NotFound`, resourceId). Roles equal the current membership; a client cannot select a role.
- **DEV021-AC-04** Switcher denial shows a reason (scope / session / unavailable) without enumerating the target and keeps the current URL/context.
- **DEV021-AC-05** A denied/stale vessel at the destination shows a reason, never falls back to another vessel, hides old context data and offers "Choose another vessel".
- **DEV021-AC-06** With an unsaved form, choosing a vessel opens the workspace Stay/Discard dialog before any context request; Stay keeps the typed draft and sends no switch request; Discard is explicit and then the destination re-verifies the context.
- **DEV021-AC-07** While a save is in flight (or its outcome is uncertain) the switch is blocked with a reason and no request.
- **DEV021-AC-08** TR/EN plus all 17 catalogs complete; keyboard/focus behaviour of the chooser unchanged; RTL relies on existing logical properties.
