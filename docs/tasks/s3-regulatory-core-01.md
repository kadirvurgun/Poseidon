## Concrete gap and authored correction

The trace handler captured `TrustedActor`, human authority appointments and/or its dedicated audit-reader assignment before multiple asynchronous database reads. Its later private event query and response used those captures. An operator withdrawal or change to the current actor, tenant, role, permission, vessel scope, decision type/subject or audit-reader binding during the request could therefore expose the previously authorized private rationale, recorded decision or hidden event metadata in the pending response. Beginning a new request correctly reevaluated the configuration; the in-flight response lacked that boundary check.

[HumanReviewEndpoints](../../backend/Poseidon.Api/HumanReviewEndpoints.cs) now snapshots the effective server-resolved actor scope and the exact selected human/reader appointments. Before private paging, after all asynchronous source lookups and after durable read-audit persistence, it calls `ActorResolver` again against the current `FederationSettings` membership and reselects current exact appointments. It does not rebuild authority from unchanged cookie/IdP role claims. A changed capture returns the existing attributed `trace_reader_required` 403 without the prepared payload. Permission and vessel-grant sets and authority appointments are compared in deterministic order, so an equivalent operator reload with reordered arrays stays authorized. Changes to unrelated objects' appointments do not enter the selected exact-object appointment set.

The defined boundary is the final live configuration check immediately before constructing the successful response result. This closes withdrawals observed by that check, including withdrawals during prior database or read-audit awaits. It is not a serializable revocation transaction covering socket writes or a promise that a change after the check can recall already emitted bytes. A withdrawal during audit persistence can leave the earlier read-success observation followed by a final attributed denial; no business mutation is performed. Historical `asOf` never restores an old grant. A later request is authorized under the newly configured context; a changed type/subject/actor may retain a generic trace but cannot recover a private event assigned to the former context.

No database schema, migration, fixture entity, route, payload shape, public DTO or mutation catalog denominator changes. Source qualification, SoD verification, exact file scope, decision recording/signature semantics, incomplete drafts and UNKNOWN behavior remain unchanged. No human authority, verification, credential, permit, evidence or receipt is added to normal seed/startup.
