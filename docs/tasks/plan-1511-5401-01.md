## Design

- **Registry (code)** `backend/Poseidon.Domain/ParameterRegistry.cs`; **contract** `contracts/parameters.v1.json` (`definitions[12]` + `inventory[354]`), regenerated by `py scripts/parameter_inventory.py` from the pinned DOCX (hash-checked, fails if the 354-key set changes). Definitions are product contract, not tenant data: no tenant can create a key (CFG3-T23).
- **Policy vs technical value**: `valueClass` POLICY / PARAMETER / TECHNICAL is reported on every definition and resolution. `ownerVerification` is `OWNER_ADAPTER_NOT_REGISTERED` for POLICY_REF and domain PARAMETER (owner validation/impact adapters do not exist), `NOT_REQUIRED` for TECHNICAL_PARAMETER and INVARIANT. `positiveUseAllowed` is true only for a CURRENT RESOLVED technical value or product invariant; a resolved policy/domain value is still not a positive operational gate.
- **Persistence** (schema `config`, migration `20261118194140_ParameterRegistryFoundation`): `ParameterRoots` (tenant + key + security scope + exact selector hash, CAS `xmin`, revision counter, pending pointer), `ParameterRevisions` (append-only body, `DeclaredUnverified` with author / `SyntheticUnverified` without), `ParameterDecisions` (append-only APPROVED/REJECTED, `SelectedFrom`), `ParameterCommandReceipts` (tenant-unique key). Database triggers: revisions/decisions/receipts immutable incl. TRUNCATE, root identity immutable and revision +1, root never deleted, decision requires decider ≠ author, approval only for `DeclaredUnverified`, never before `EffectiveFrom`/decision, never at/after `EffectiveTo`. EF guard mirrors these before audit generation; all writes go through audited `SaveChanges` (no ExecuteUpdate/raw SQL).
- **Resolver**: server-built chain (VESSEL→its COMPANY→TENANT→GLOBAL), filtered to the definition's allowed scopes, starting at the most specific allowed level. Latest selection of a root at `effectiveAt` and `knownAt` wins (append-only cutover; an earlier revision never resumes after expiry). INHERIT climbs; no value + BLOCK → UNCONFIGURED; APPROVED_DEFAULT → product default only if deployment-accepted (none is).
- **Decision on "most specific scope wins"**: implemented as 54.01 paragraph:28 states — a more specific value overrides; a parent value is used for a child scope only through an explicit approved INHERIT (no definition in the source uses `fallback INHERIT`). This is narrower than an implicit fallback and is deliberate.
- **Maker-checker**: local `ParameterGovernance` (PR #23 `SeparationOfDuties` is not merged). Identity is the server-resolved actor id; unknown author/decider fails closed. Cross-account same-person detection needs the 52.02 person/account model (PR #28) — open item.
- **Endpoints** (native 58.03 profiles, see below): `GET /api/v1/parameter-definitions` (`config.read`), `GET /api/v1/effective-parameters` (`config.resolve`), `GET /api/v1/parameter-changes/{id}` (`config.read`), `POST /api/v1/parameter-changes` (`config.draft`), `POST /api/v1/parameter-changes/{id}/commands/approve` (`config.approve`), `.../reject` (`config.reject`). All require `DirectoryRead` plus tenant-wide read/manage; writes require trusted role attribution. VESSEL/COMPANY identities and roots outside the actor's tenant/vessel scope are 404.
- **Seed**: optional `ParameterFixtures.AddMissingAsync` (administrative import only, not wired to normal seed import, like `FleetCatalogDraftFixtures`): one FICTIONAL pending `INHERIT` proposal per tenant for `rpt.export.rows`, no value, no author, `SyntheticUnverified`; approval refused (domain + trigger), rejection allowed, reseed preserves operator decisions. No approved value, decision, deployment acceptance or owner binding is seeded.
