## Implemented contract and limits

`GET /api/v1/audit` accepts only optional `vesselId`, `resourceId`, `entityType`, `action`, `limit`, `cursor`. UUID filters are exact nonempty D format, one value each. Type/action come from closed vocabularies. Each value is ≤256 characters. Limit defaults25, maximum100. Cursor is bounded `cutoffTicks~lastTimestampTicks~lastUUID`; ordering is OccurredAt DESC, UUID DESC. Cursor is navigation, never authority; all scope is reapplied even when a cursor came from another scope. Total is counted from the fully scoped, filtered cutoff set. This is deterministic keyset navigation, not a database snapshot retained across HTTP requests: transactions that started before the cutoff and commit later may become visible. No global total or unrestricted history export exists.

`GET /api/v1/audit/{id}` uses the identical scope before reading metadata. `/{id}/revision` resolves only the exact stored immutable revision through the caller's current vessel/catalog authorization, with a typed `AuditEvidenceDto` and404 on absence. It cannot fetch an arbitrary URL, payload or file. Catalog reads additionally require explicit regulatory.draft.read and tenant-wide scope. Receipt keys/fingerprints and raw EntityId strings are never projected; already-authorized rows can be enriched only with that tenant/resource/correlation's observed committed xmin. No historical xmin is guessed.

New safe summaries allow numeric GT/BP, Kind, CompanyId and revision values. Code/Name carry changed-field markers with values withheld. ContentJson carries only a revision reference; arbitrary content is not serialized into audit. Resource before-version and committed version are nullable where not actually observed. Imports have explicit SeedImport source; API contexts have WebCommand source. No device claim is invented. Capability context is the trusted membership's whitelisted permissions; there is no approved operational role catalog to invent.

Current online directory/profile/register commands are preparation commands, with no source-defined human safety decision/reopen/override reason input. `NotRequiredForCommand` records that semantic distinction; it is not a user-supplied reason. Historical reason stays null. Future decision/override/publish commands must require their own bounded, source-required reasons and expert authority. They are not implemented here.

SecurityEvents remain sensitive separate observations; **audit.read does not authorize any SecurityEvents endpoint**. There is no raw log, stack trace, request body, token, health/PII or export viewer. One successful history request appends a bounded security observation, outside business history. Mandatory observation failure returns503 and withholds results. Generic framework binding/routing errors before a handler are not relabeled as successful action observations; this package does not claim every HTTP request has complete action auditing.

Observability contract: the server generates X-Correlation-ID and uses it for security/business audit joins; request-supplied correlation is not accepted as authority. Meter `Poseidon.Audit` v1.0.0 emits `poseidon.audit.security.persisted` (committed security events), `poseidon.audit.security.unavailable` (failed/missing-store write attempts) and `poseidon.audit.security.duration` (milliseconds per security-writer attempt). There are **no labels**. Operators can alert on unavailable increments and writer latency; these signals describe the security writer, not overall product/EF-transaction health, sync/file readiness or operational safety. No actor/tenant/vessel/resource/correlation values enter metric dimensions. `AuditTelemetryTests` authors actual success/outage and zero-label assertions; execution is DEFERRED.
