## Exact scheduling, persistence and source semantics

`NotificationScheduler.Enabled` defaults false. Missing/invalid scopes, routing, actor, issuer/subject, role, required capabilities, vessel grant/mode or database reference remain unavailable; no fallback actor, production credential or scheduled route is seeded. Configuration supplies `Scopes[{tenantId,vesselId,serviceActorId,roleId}]`, interval, lease, timeout, source batch size and maximum scopes per tick. Lease must exceed timeout plus five seconds. Actual operator configuration/deployment is separate and has not been activated here. No OS/Codex automation, container/preview changes, external message or delivery provider was used.

A normal attributed lease acquisition commits first. Work effects, episodes, source xmin fence, lifecycle events, dispatch cursor and lease release commit atomically second. Cancellation, deadline, revoked service authority, serialization failure or lost lease rolls back that work; only the earlier expiring control-plane lease may remain. Concurrency/serialization/deadlock/provider errors go through PostgresFailure. No raw SQL business write, bulk bypass or administrative context is exposed to HTTP.

The source fingerprint contains the explicit adapter version `notification-source-episodes-v1`, plan revision, exact selected observation/time and deterministic calculated due/state/reason/algorithm plus actual asset/job/owner context. It excludes `readAt`, `now` and elapsed sampling clocks. The adapter version deliberately distinguishes newly evaluated source semantics during legacy bootstrap; retired records are not reopened. Existing immutable ObservationId pinning is preserved; another reading does not silently replace it. Unresolved Due assessment is not NotDue. Removing every rule makes policy Unavailable; it does not manufacture a known inactive episode. Real known boundaries observed between polls are retained; an entire inactive/active cycle never observed by the scheduler cannot be reconstructed or claimed.

[New migration](../../backend/Poseidon.Persistence/Migrations/20261104210000_NotificationScheduling.cs) and [model/snapshot](../../backend/Poseidon.Persistence/Notifications.cs) add DispatchState/Episode entities and the epoch component of unique source-trigger identity. Normal audited SaveChanges, tenant filters, scoped FKs, immutable ownership, revision/monotonic epoch/no-delete/no-truncate guards apply. Downgrade fails closed if recurring history cannot fit the older unique identity. Migration target designer/scaffold/parity/application remain deferred to the real PR gate. [Optional fixtures](../../backend/Poseidon.Persistence/Seeding/NotificationFixtures.cs) add only blank unleased dispatch and null/unobserved episode metadata against synthetic plans; no evaluation time, false state, service account, delivery, acknowledgement or authority is invented. Normal importer totals remain unchanged; existing reseed-preservation regression covers add-missing behavior.
