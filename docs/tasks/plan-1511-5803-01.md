## Delivered design

- `contracts/endpoint-profiles.v1.json` — machine-readable registry, embedded into the API (`Poseidon.EndpointProfiles`).
  - `profiles[]`: transport contracts. Every current profile is `conformance: NATIVE_PRE_58_03` with `targetProfile: COMMON-1`
    and an explicit `gaps[]` list. No native profile uses a canonical 58.03 ProfileId (paragraph:161); the loader rejects that.
  - `endpoints[]`: exactly one entry per mapped `method + route template` (292 today: 177 GET, 85 POST, 30 PUT). Observed fields
    (operationId, anonymous, authorization policies, request media/schema, concurrency evidence, S1 security operation, owner type)
    are compared with the actual host; `profileId` and `deviations[]` are reviewed edits.
  - `exclusions[]`: Development-only OpenAPI document and lab SPA fallbacks.
- `backend/Poseidon.Api/EndpointProfiles.cs` — loader/validator (`Observe`, `Validate`, `Find`, `Match`), idempotency mode set and
  the OpenAPI operation transformer that emits `x-poseidon-profile` on every operation. The registry is never consulted for
  authorization.
- `scripts/endpoint_profiles.py` — merges a host dump into the contract, preserves curated fields, marks new endpoints
  `UNASSIGNED` (which the API refuses to load, so an unprofiled endpoint cannot ship).

Profiles (endpoint counts): NATIVE-READ-1 (173), NATIVE-COMMAND-1 (89, header Idempotency-Key + durable actor/key receipt,
body expectedVersion CAS, stale 409 `version_conflict`), NATIVE-OFFLINE-1 (11, body commandId outcome), NATIVE-CLIENT-ID-COMMAND-1
(6, client/staged resource id), NATIVE-OBSERVATION-COMMAND-1 (5, access grants/extraction suggestions, no business effect),
NATIVE-STATE-COMMAND-1 (2, state-idempotent revoke/refresh), NATIVE-SESSION-1 (2), NATIVE-PUBLIC-1 (2), NATIVE-SESSION-COMMAND-1 (1),
NATIVE-DENIED-1 (1, S1 AlwaysDenied).

## Gaps and follow-ups (not closed by this package)

- No endpoint implements a 58.03 canonical profile yet. Native gaps per profile: RFC7807 COMMON-1 envelope (`type/title/status/instance/traceId/retryable/fieldErrors`), `If-Match`/ETag with 428/412, tenant+commandId durable dedup, `{commandId,data}` envelope, `GET /api/v1/commands/{commandId}` common receipt, 202 in-flight status, signed cursors and registered list limits. Converting a running endpoint needs a compatibility adapter and contract test (paragraph:8, :257).
- 58.03 paragraph:57 fields not yet in the registry: commandType, request/response schema version, permissionKey, sensitiveFieldProfile, asyncEffect, maxBodyBytes, retryClass. They need the 54.01/54.02 catalogs and are not invented here.
- Header-key deviations (`IDEMPOTENCY_KEY_NOT_REQUIRED`): `ImportUpload`, `ImportMappingDraft`, `ImportPreview` read no Idempotency-Key although they are NATIVE-COMMAND-1 endpoints. Follow-up: add header-key receipts with a frontend client change (not low-risk in this package).
- `OfflineReplay` (crew) ignores the client Idempotency-Key and derives it from the body commandId (`IDEMPOTENCY_KEY_DERIVED_FROM_COMMAND_ID`).
- 15 commands reject malformed bodies in framework parameter binding before the handler: empty 400, no `code`, no audit (`BINDING_REJECTION_BEFORE_HANDLER_WITHOUT_ENVELOPE`). 18 endpoints (17 GET + logout) return some errors with an empty body (`NON_JSON_ERROR_ENVELOPE`). Follow-up: a shared binding-failure envelope; it changes many responses, so it is not part of this package.
- Probe reach: missing-CSRF requests reached the CSRF check on 67/115 commands and missing-key requests reached the key check on 47/86. The others were refused earlier (scope gate, query, binding, 404) with no effect. For those, the profile assignment comes from source review, not from the probe.
- Fixed in this package: `DocumentEndpoints` problem responses had the machine code only in `title`; they now also carry `code` and `correlationId` (additive).
