## Delivered design

- `contracts/endpoint-profiles.v1.json` — machine-readable registry, embedded into the API (`Poseidon.EndpointProfiles`).
  - `profiles[]`: transport contracts. Every current profile is `conformance: NATIVE_PRE_58_03` with `targetProfile: COMMON-1`
    and an explicit `gaps[]` list. No native profile uses a canonical 58.03 ProfileId (paragraph:161); the loader rejects that.
  - `endpoints[]`: exactly one entry per mapped `method + route template` (327 after the 19.11.2026 main merge: 194 GET, 101 POST, 32 PUT). Observed fields
    (operationId, anonymous, authorization policies, request media/schema, concurrency evidence, S1 security operation, owner type)
    are compared with the actual host; `profileId` and `deviations[]` are reviewed edits.
  - `exclusions[]`: Development-only OpenAPI document and lab SPA fallbacks. The loader accepts only `/openapi/…`, `/app/…` and
    `/agents`; any exclusion under `/api` (or containing `..`) is rejected, so no API endpoint can be excluded from profiling.
- Fail closed at runtime: `EndpointProfiles.StartupValidation` (first registered `IStartupFilter`, therefore outermost) runs
  `Validate` against the host `EndpointDataSource` after the whole pipeline is configured, in every environment. An invalid registry,
  a reserved `UNASSIGNED` profile id or a mapped endpoint without an exact profile stops the host from starting.
- `backend/Poseidon.Api/EndpointProfiles.cs` — loader/validator (`Parse`, `Observe`, `Validate`, `Find`, `Match`), idempotency mode set and
  the OpenAPI operation transformer that emits `x-poseidon-profile` on every operation. The registry is never consulted for
  authorization.
- `scripts/endpoint_profiles.py` — merges a host dump into the contract, preserves curated fields, marks new endpoints
  `UNASSIGNED` and exits 1 (the API refuses to load it and the host refuses to start, so an unprofiled endpoint cannot ship).
  Unit tests: `scripts/test_endpoint_profiles.py`.

Profiles (endpoint counts): NATIVE-READ-1 (190), NATIVE-COMMAND-1 (103, header Idempotency-Key + durable actor/key receipt,
body expectedVersion CAS, stale 409 `version_conflict`, fresh re-read on replay), NATIVE-COMMAND-STORED-OUTCOME-1 (4, same header-key/CAS
contract but a replay returns the stored receipt outcome after current authorization: 54.01 parameter changes, vessel profile field sources), NATIVE-OFFLINE-1 (11, body commandId outcome), NATIVE-CLIENT-ID-COMMAND-1
(6, client/staged resource id), NATIVE-OBSERVATION-COMMAND-1 (5, access grants/extraction suggestions, no business effect),
NATIVE-STATE-COMMAND-1 (2, state-idempotent revoke/refresh), NATIVE-SESSION-1 (2), NATIVE-PUBLIC-1 (2), NATIVE-SESSION-COMMAND-1 (1),
NATIVE-DENIED-1 (1, S1 AlwaysDenied).

## Gaps and follow-ups (not closed by this package)

- No endpoint implements a 58.03 canonical profile yet. Native gaps per profile: RFC7807 COMMON-1 envelope (`type/title/status/instance/traceId/retryable/fieldErrors`), `If-Match`/ETag with 428/412, tenant+commandId durable dedup, `{commandId,data}` envelope, `GET /api/v1/commands/{commandId}` common receipt, 202 in-flight status, signed cursors and registered list limits. Converting a running endpoint needs a compatibility adapter and contract test (paragraph:8, :257).
- 58.03 paragraph:57 fields not yet in the registry: commandType, request/response schema version, permissionKey, sensitiveFieldProfile, asyncEffect, maxBodyBytes, retryClass. They need the 54.01/54.02 catalogs and are not invented here.
- Header-key deviations (`IDEMPOTENCY_KEY_NOT_REQUIRED`): `ImportUpload`, `ImportMappingDraft`, `ImportPreview` read no Idempotency-Key although they are NATIVE-COMMAND-1 endpoints. Follow-up: add header-key receipts with a frontend client change (not low-risk in this package).
- `OfflineReplay` (crew) ignores the client Idempotency-Key and derives it from the body commandId (`IDEMPOTENCY_KEY_DERIVED_FROM_COMMAND_ID`).
- The deviation list is complete per the static source review (P5803-AC-08) plus the probe. `BINDING_REJECTION_BEFORE_HANDLER_WITHOUT_ENVELOPE` (24 at first review; 25 after the 19.11 merge adds vessel profile field history `offset/limit`): 16 commands with a JSON body bound by the framework (malformed JSON → empty 400, no `code`, no audit outside Development) and 8 GETs with typed query values (`vessel` Guid on the four flat technical reads; `int? offset/limit` on companies, vessels, regulatory-profile history, workspace search). `NON_JSON_ERROR_ENVELOPE` (20 at first review; 23 after the 19.11 merge adds critical-states and vessel profile fields/history): 19 GETs + logout whose handlers can return `Results.NotFound()/BadRequest()/Forbid()/StatusCode(403)` without a body (audit record, company, vessel, regulatory profile and history, source/requirement draft list/read/history, system health, current assignment, owning inputs, personal files, crew position policy, poseidon-today, why-engine, workspace search). Follow-up: a shared binding-failure envelope and JSON bodies for these results; it changes many responses, so it is not part of this package.
- Static review method and limits: `Results`/`TypedResults` empty-body calls are found by regex in `backend/Poseidon.Api/**/*.cs`, attributed to the innermost compiled method via portable PDB sequence points, and linked to endpoints by an IL call graph walked from each host handler `MethodInfo`. Calls through interfaces/virtual dispatch into other assemblies are not followed; any occurrence no handler reaches fails the test. `Results.Challenge(..)` is excluded (OIDC login redirect); pipeline-level 401 challenges and authorization-policy 403s are produced by middleware, not handlers.
- Probe reach: missing-CSRF requests reached the CSRF check on 67/115 commands and missing-key requests reached the key check on 47/86. The others were refused earlier (scope gate, query, binding, 404) with no effect. For those, the profile assignment comes from source review, not from the probe. The probe is the partial runtime check `DirectoryWorkspaceTests.Registered_command_and_read_profiles_are_enforced_by_the_actual_host`, defined in `tests/Poseidon.Api.Tests/EndpointProfileRegistryTests.cs` (partial class).
- Fixed in this package: `DocumentEndpoints` problem responses had the machine code only in `title`; they now also carry `code` and `correlationId` (additive).
