## Delivered owning behavior

- Three EF entities in the Technical module own the defect head, immutable revisions and actor/key receipts. Optional Asset/AssetRevision links are exact tenant/vessel/revision relationships, with the originally established actual head version and source JSON hash retained as immutable pins. Receipt foreign keys bind the actual own revision and committed PostgreSQL version. Optional incomplete synthetic fixtures create only missing declaration heads/revisions with all facts Missing and no asset, deadline, safeguard, approval, verification or user receipt. Operator revisions survive repeated import. Nothing is activated at startup.
- Source-authored migration/snapshot include tenant relationships, nullable-pin completeness constraints, xmin concurrency, one-revision head guards, immutable history/receipt guards and truncate denial. All ordinary mutations use attributed EF SaveChanges in SERIALIZABLE transactions; PostgresFailure alone classifies PostgreSQL failures. No business raw/bulk mutation, actor construction, administrative request context or cleanup bypass is exposed.
- `/api/v1/defects?vessel=UUID` exposes list/capabilities, detail/history, create and update. Collection/history paging is bounded25; only vessel and permitted offset query keys are accepted. The strict command requires id, expectedVersion, fields, sourceVersion and explicit asset (nullable). Permission defect.read additionally requires equipment.read and actual tenant/Ship/Tug scope; writes also require defect.write, real trusted role attribution and edit-vessel scope.
- Exact same-actor UUID keys retain canonical request identity, fields, asset/source pins, resource/version and durable outcome. Changed bodies conflict; stale writes conflict. Save/replay outcomes remain immutable record snapshots with currentRevision=false/canEdit=false. Every history row is read-only, including the row whose CurrentRevision annotation matches the current head. Only an actual current owning GET establishes editability.
- The temporal projection is explicitly separate from durable facts. DefectPolicy.Assess refreshes temporary-measure expiry from the current server time after the last response fence, including current reads, history and receipt recovery. Its AssessedAt and declared deadline state can change while receipt bytes, committed facts/version/hash and safety qualification remain unchanged. Thus exact command recovery means the exact committed effect/facts, rather than byte equality of a time-relative response observation. No deadline observation grants closure or asserts that a measure is effective.
- The actual equipment context reader captures the current Asset head xmin rather than guessing from pre-save AssetRevision JSON. New/changed pins require the current source; unchanged established historical pins can remain on subsequent declarations while source read rights persist. Current-only source context requests for older revisions return asset_context_stale rather than fabricating historical xmin. A defect's original pin remains visible as immutable metadata under its own scope.
- Fresh response fencing opens a trusted tenant context outside an old transaction snapshot. It captures bounded immutable asset JSON/hash matches, then composes returned/current defect versions, current-and-returned asset origins and prospective current source pins into ONE final vessel SQL predicate. Actor rights are synchronously re-resolved after awaits and after independent success audit. Current asset restriction changes cannot bypass controls through history, old receipts, clearing a link or stale snapshot assumptions.
- Independent HTTP Attempted/Success/denial audit supplements the transactional EF audit. Safe summaries retain real actor/role/scope, operation names DefectCreate/DefectUpdate, PREPARATION_COMMAND technical provenance and actual before/after revision/version. They exclude narratives, source JSON, quantities, hashes and request/response bodies. Postcommit scope/audit loss returns503 command_outcome_withheld without exposing private facts or rolling back a committed transaction; exact same-owner command recovery remains available only after current authorization returns.
