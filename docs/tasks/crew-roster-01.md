## Authored behavior and boundaries

`crew.Persons` is the tenant root with nullable declared name/employee number, Unknown employment state, provenance, nullable observed time and PostgreSQL xmin. `crew.Positions` contains tenant/vessel-local operator references for rank/capacity/department; no legal catalog or competence approval is fabricated. `crew.Assignments` links the real tenant Person/Vessel/Position using composite FKs, typed periods, watch/contract fields, provenance, revision and xmin. Immutable `AssignmentRevisions` store typed opaque references and periods; personal/watch text snapshots are deliberately unavailable. No arbitrary JSON field bag is used.

Dates are nullable in drafts. The technical reservation convention is `[from,to)` and `to>from`; missing start/end does not imply Ready/No/NotApplicable. A PostgreSQL tenant/person date-range exclusion constraint arbitrates concurrent reservations across vessels, with a serializable API transaction and optimistic xmin updates. This conservative draft reservation convention is an engineering choice pending source lifecycle/period reconciliation, not a maritime legal rule. The model does not invent an operational rank/capacity/status list. Operational submission/sign-on/off transitions remain unimplemented; ordinary data entry persists Draft without an invented sign-off gate.

API routes under `/api/v1/vessels/{vessel}/crew`: list/paging, scoped profile, safe history, position references/create, assignment create/revise and independent person edit (`PUT /{assignment}/person`). Server-provisioned `crew.read`, `crew.write`, `crew.identity.read/write`, `crew.history.read` and `crew.position.write` supplement existing real vessel scope. No directory write or vessel grant implicitly grants sensitive access. New permission names are engineering capabilities requiring trusted provisioning, not asserted source role appointments. Existing Person reuse requires its existing assignment in the same vessel; a cross-vessel HR person selector/transfer flow is still a gap. There is no unscoped person lookup, PII search or export.

All mutations use attributed audited SaveChanges. Assignment/history/receipt and Person/receipt writes are atomic. Actor-scoped immutable command receipts pin result version/revision; same UUID/key retry returns the same safe committed metadata, not a personal snapshot. Conflicting key reuse, stale versions, concurrent overlap or duplicate effects return safe conflicts. Person edits use an independent xmin and do not rewrite assignment lineage. Required real read/attempt/denial observations withhold results on audit failure. Framework pre-handler binding/routing failures retain the existing auditing limitation; this is not complete HTTP auditing or privacy/retention compliance.

Name/employee number are withheld in the server projection unless separately provisioned identity access exists. Health/contact/credentials and all unresolved sensitive profile fields remain withheld/unavailable; no directory grant grants these. Search parameters are rejected rather than searched against hidden fields. Scope is checked before joins, paging, detail/history or error output. No raw body, PII or credential is added to audit summaries/metrics/logs. Generic action-history type allowlisting continues to exclude new Person/crew entities; the crew history endpoint has its own explicit capability and does not expose historical personal text.

Synthetic import adds one clearly FICTIONAL/unverified Person, null-rank/capacity Position, incomplete Draft Assignment and initial revision per existing synthetic vessel. Deterministic entity IDs and add-missing imports preserve operator edits. Three vessels add12 actual audit writes (prior fixture34→46), not fabricated audit/receipt data; seed expectations are updated. No real credentials/documents/medical decisions/appointments or dates are seeded.

Actual React API consumers implement roster/profile, person edit and assignment draft forms at `/app/crew-roster/{vessel}` and `/crew-profile/{assignment}`; vessel links preserve context. TR/EN, responsive forms/tables, loading/empty/denied/error/expired, native dirty-navigation dialog, browser back/forward navigation and frozen uncertain attempts are authored. An uncertain request retains its UUID/key/body for retry; conflicts require discard/reload. Views suspend when hidden and reauthenticate on return; identity changes/denials clear projections/editor data. Nothing is persisted in browser storage. Browser/runtime accessibility and all such behavior remain unverified.
