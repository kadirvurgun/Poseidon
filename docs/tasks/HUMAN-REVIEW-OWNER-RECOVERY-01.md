## Concrete correction

Previously the component froze a body/key, but reused caller CSRF without original actor/tenant binding. After a lost response, Discard erased the unresolved command and allowed a new key. Later denial disabled retry while dirty state prevented reload. POST denial retained private trace/text in the DOM. Success cleared the command before optional readback and retained no known receipt.

[Recovery controller](../../frontend/src/product/use-human-review-recovery.ts) now binds an in-memory draft/attempt to the original actual session and immutable evidence/control anchor. It captures exact authority/operation/capability/role/policy, kind, nullable route stream ID, serialized body, UUID idempotency key and expected next revision. A new stream ID is generated by the server; no body UUID is invented.

Initial send and exact retry fetch the actual current session, read current trace/authority, then refresh the same-owner session again for fresh CSRF before POST. The receipt is strictly decoded and command-bound, checked against original actor/role/revision/policy, and followed by a same-owner session fence. Authority is never inferred from UI roles or permission labels. Current-owner hints travel from [ProductApp](../../frontend/src/product/ProductApp.tsx) through [RegulatoryRegister](../../frontend/src/product/RegulatoryRegister.tsx) and [ControlEvidence](../../frontend/src/product/ControlEvidence.tsx), but server/session checks supply authority.

An already UNKNOWN attempt survives every later denial/conflict/read/timeout failure. Its body/key cannot be edited, discarded, replaced or implicitly resent. Explicit **Retry source read** restores only the original owner's current source visibility; eligible retry still sends the exact frozen command. Permanent authority/material-lineage denial can remain unresolved; this package creates no receipt lookup endpoint or reconciliation override. An initial definite rejection before any unknown outcome may release that attempt while retaining its owner-bound unsent draft for explicit correction/discard.

Private draft/history/recording fields are withdrawn when current owner/access/source scope is unavailable. Render scope, mounted/abort and command refs fence late reads, writes and stale edit closures. Offline withdraws authority. Discard of an unsent local draft requires a newly fetched actual original-owner session, but does not require restored write authority or restore protected DOM. Offline may retain the visible disabled Discard control; it cannot supply that fresh proof. UNKNOWN is never discardable. No browser persistence of private human text is introduced.

A valid owner-bound receipt remains known and read-only through failed optional trace readback, with generic **Draft saved.**; it is never turned into another POST. Fresh-source recovery keeps that confirmation read-only until deliberate local reset/new-review choice. Existing trace/source URLs remain. The confirmation does not assert verification, operational approval or source effectiveness.

Existing `onDirty/onSaving` aggregation carries the unresolved navigation barrier across vessel/register/workspace changes, including already-open Discard confirmation callbacks. Parent fields remain locked. The sibling file component remains unchanged and mounted; its container becomes inert during a bound review, and a pending upload-dirty callback cannot unmount the human command. HumanDecisionTrace itself has no file input/arrayBuffer path.
