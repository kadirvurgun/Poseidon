## Design decisions

- **P5202-D01 — migration from config.** `FederationSettings.Memberships` stays the
  operator-provisioned *grant source* (permissions, tenant-wide scope, appointments). Persisted
  `identity.Accounts`/`identity.Memberships` are a **narrow-only lifecycle overlay** imported
  deterministically by `POST /api/v1/memberships/import` (membership id = SHA-256(tenant, actor)).
  Effective actor = config grant ∩ persisted state: non-Active ⇒ no actor; vessel grants are the
  intersection; `RoleContext`/`ActiveCompanyId` survive only when persisted and config agree.
  A persisted row without a config entry grants nothing. No persisted row ⇒ bootstrap source governs.
- **P5202-D02 — session revalidation.** `MembershipSessionGate` runs after authentication and
  before authorization on every request. Persisted non-Active state, identity conflict or a
  session `poseidon:arv` stamp older than `Membership.AccessRevision` makes the request anonymous
  (401), deletes the cookie and writes `SessionRevalidation/membership_inactive`. Login
  (`OnTokenValidated`) denies non-Active memberships and stamps the current access revision.
  DB unavailable ⇒ 503 (no fallback to old authority).
- **P5202-D03 — delegation.** Persisted, approved by a `membership.manage` admin who is neither
  source nor delegate (maker-checker); scope ⊆ source's current operator permissions, never
  `membership.*`/`delegation.*`/`audit.read`/`directory.read`; window ≤ 90 days (technical ceiling,
  not an approved 54.01 `delegation.max_days` value); state computed from server `TimeProvider`.
  Suspend/revoke of either side revokes linked delegations. Delegations are **not merged into
  `TrustedActor.Permissions`**; they are exposed through `ICurrentMembershipResolver` for the
  54.02 exact action resolver, which must record actor + on-behalf-of + delegationId.
- **P5202-D06 — delegation scope + reason (QA follow-up, 52.02 paragraph:102).** A delegation stores a
  scope snapshot: optional `CompanyId` plus immutable `identity.DelegationVesselScopes` rows
  (`VesselId`, `CanEdit`). At create the snapshot must be a subset of the source's CURRENT authority
  (operator grant ∩ persisted membership/grant snapshot, same rules as `ActorResolver`): unknown
  vessel, edit on a read-only vessel or a different company ⇒ 400 `validation_failed`
  (`vesselScope`/`companyId`: `exceeds_source_scope`); company and vessels both empty ⇒ `scope: required`.
  Tenant-wide read/manage is never delegated. `ReasonCode` is mandatory and closed
  (`PlannedAbsence`, `UnplannedAbsence`, `WorkloadCover`, `Handover` — technical codes, not an
  approved 54.01 catalog; no free text per the privacy decision). Rows predating the snapshot are
  migrated as `LegacyUnscoped` (migration-only marker, rejected for new rows) and are never effective.
- **P5202-D07 — security resume.** Resuming a membership whose `StatusReason` is `SecuritySuspension`
  requires `membership.security.suspend` (membership.manage alone ⇒ 403 `permission_denied`); it sets
  `StatusReason = SecurityResume` and closes that membership's open `AccessRecoveries` case exactly once
  (`ResolvedAt`, `Resolution = SecuritySuspensionResumed`, EF-audited). An administrative suspension
  stays with membership.manage (the security authority alone ⇒ 403).
- **P5202-D08 — command fence and import result.** Each membership command re-reads the acting
  administrator's persisted membership inside its SERIALIZABLE transaction (non-Active or newer
  access revision ⇒ 409 `conflict_changed`); a COMMIT-time 40001 is rolled back safely and reported
  as 409 instead of 500. Import commits one audited SaveChanges per entry (EF savepoint): an
  issuer/subject or actor id already bound in another tenant skips only that entry
  (`identity_bound_other_tenant`); other closed skip reasons are `invalid_configuration`,
  `duplicate_configuration`, `actor_conflict`. No cross-tenant query is issued. Skipped identities
  stay governed by the operator configuration (no persisted row in this tenant). The original result
  (counts + closed skip codes, no identity values) is stored in the receipt and returned on replay.
  `MembershipDto.Administrator` uses the same `ActiveAdministrators` predicate as the last-admin count.
- **P5202-D04 — last admin.** Admin = operator grant with `membership.manage`, tenant-wide manage,
  trusted role and `directory.read`, and persisted Active (or not yet imported). Voluntary
  suspend/revoke of the last active admin ⇒ 409 `last_admin`. Forced path is a separate exact
  action `security-suspend` (`membership.security.suspend`), never a client `forced` flag; it is
  not blocked and records `identity.AccessRecoveries` (RECOVERY_REQUIRED) without creating any
  hidden account. The count runs in the same SERIALIZABLE transaction as the change.
- **P5202-D05 — interface for PLAN-1511-5402.** `ICurrentMembershipResolver.ResolveAsync(HttpContext)`
  → `CurrentMembership` (actor, tenant, membership id, status, access revision, persisted flag,
  active company, effective received delegations). 5402 consumes this; it must not read
  `FederationSettings` or `identity.*` tables directly.
  **Delegation contract:** each `CurrentMembership.ReceivedDelegations[]` (`EffectiveDelegation`) carries
  `Permissions`, `ActiveCompanyId`, `VesselGrants` (each with `CanEdit`), `ReasonCode` and
  `TenantWide = false`, all intersected at request time with the source's CURRENT authority
  (permission, vessel, edit right or company removed at the source ⇒ narrowed; nothing left ⇒ the
  delegation is omitted). A delegated permission may be applied ONLY inside that delegation's own
  company/vessel scope — never with the delegate's own `TrustedActor` vessel grants, company or
  tenant-wide flags — and the action records actor + on-behalf-of (`DelegatorActorId`) + `DelegationId`.
- Audit reason code: the seven new critical writes reuse `PREPARATION_COMMAND` because adding a
  reason code requires a coordinated audit vocabulary + 17-locale i18n change (open item).

## Open items

- Commit-time revalidation for in-flight business commands (revoke during an already-authorized
  non-membership command) belongs to the 5402 commit fence; the gate covers every *next* request.
  Membership commands themselves re-check the actor in-transaction (P5202-D08).
- **P5202-OPEN-01 (assigned: PLAN-1511-5402 integration).** Owner/verifier/qualifier eligibility of
  *other* actors still reads `FederationSettings.Memberships` only and ignores persisted
  suspension/revocation: `backend/Poseidon.Api/CertificateRenewalEndpoints.cs:29` (`Owners`),
  `backend/Poseidon.Api/ControlEvidenceEndpoints.cs:77` (eligible owners/verifiers),
  `backend/Poseidon.Api/CurrentRegulatoryContext.cs:22` (current qualifier). A suspended or revoked
  person can still be listed/selected as owner, verifier or qualifier until 5402 routes these
  through `ICurrentMembershipResolver`/persisted state.
- Invitation, activation, close/reopen, expiry worker, identity rebind, person link, service
  accounts, per-session listing/revoke and preference routes of 52.02 G are not implemented.
- Free-text reasons are not stored (closed reason codes only) pending a privacy decision.
- Config grant changes after import: only **vessel grants, role context and active company** are
  fail-closed (intersected with / must equal the imported snapshot) until a future audited
  grant-sync command. **Permissions and the tenant-wide read/manage flags follow the operator
  configuration live** (added ones take effect immediately, removed ones disappear immediately).
  A dedicated `ACCESS_LIFECYCLE` audit reason code + i18n remain open.
- Delegation reason codes are a technical closed set pending an approved catalog; the 90-day window
  remains a technical ceiling.
- UI for membership administration is not part of this package.

## Extension (USER-ADMIN-01, 21.11.2026)

P5202-D01 still governs every identity present in `FederationSettings.Memberships` and every `ConfigurationImport`/
`SyntheticUnverified` row. USER-ADMIN-01 adds a third, explicit source: `Source = AdminProvisioned` accounts/memberships
created through the audited `POST /api/v1/memberships` command for identities **without** a config entry; their grant is
the latest immutable `identity.MembershipGrantRevisions` row. Configuration keeps precedence for its identities
(bootstrap/break-glass). Lifecycle, last-admin, delegation and session revalidation rules of this package apply
unchanged. See [USER-ADMIN-01](USER-ADMIN-01.md) UA-D01..D09.
