## Design decisions

- **P5202-D01 — migration from config.** `FederationSettings.Memberships` stays the
  operator-provisioned *grant source* (permissions, tenant-wide scope, appointments). Persisted
  `identity.Accounts`/`identity.Memberships` are a **narrow-only lifecycle overlay** imported
  deterministically by `POST /api/v1/memberships/import` (membership id = SHA-256(tenant, actor)).
  Effective actor = config grant ∩ persisted state: non-Active ⇒ no actor; vessel grants are the
  intersection; `RoleContext`/`ActiveCompanyId` survive only when persisted and config agree.
  A persisted row without a config entry grants nothing. No persisted row ⇒ bootstrap source governs.
- **P5202-D02 — session revalidation.** `MembershipSessionGate` runs after authentication and
  before authorization on every request. Persisted non-Active state, identity conflict or a
  session `poseidon:arv` stamp older than `Membership.AccessRevision` makes the request anonymous
  (401), deletes the cookie and writes `SessionRevalidation/membership_inactive`. Login
  (`OnTokenValidated`) denies non-Active memberships and stamps the current access revision.
  DB unavailable ⇒ 503 (no fallback to old authority).
- **P5202-D03 — delegation.** Persisted, approved by a `membership.manage` admin who is neither
  source nor delegate (maker-checker); scope ⊆ source's current operator permissions, never
  `membership.*`/`delegation.*`/`audit.read`/`directory.read`; window ≤ 90 days (technical ceiling,
  not an approved 54.01 `delegation.max_days` value); state computed from server `TimeProvider`.
  Suspend/revoke of either side revokes linked delegations. Delegations are **not merged into
  `TrustedActor.Permissions`**; they are exposed through `ICurrentMembershipResolver` for the
  54.02 exact action resolver, which must record actor + on-behalf-of + delegationId.
- **P5202-D04 — last admin.** Admin = operator grant with `membership.manage`, tenant-wide manage,
  trusted role and `directory.read`, and persisted Active (or not yet imported). Voluntary
  suspend/revoke of the last active admin ⇒ 409 `last_admin`. Forced path is a separate exact
  action `security-suspend` (`membership.security.suspend`), never a client `forced` flag; it is
  not blocked and records `identity.AccessRecoveries` (RECOVERY_REQUIRED) without creating any
  hidden account. The count runs in the same SERIALIZABLE transaction as the change.
- **P5202-D05 — interface for PLAN-1511-5402.** `ICurrentMembershipResolver.ResolveAsync(HttpContext)`
  → `CurrentMembership` (actor, tenant, membership id, status, access revision, persisted flag,
  active company, effective received delegations). 5402 consumes this; it must not read
  `FederationSettings` or `identity.*` tables directly.
- Audit reason code: the seven new critical writes reuse `PREPARATION_COMMAND` because adding a
  reason code requires a coordinated audit vocabulary + 17-locale i18n change (open item).

## Open items

- Commit-time revalidation for in-flight requests (revoke during an already-authorized command)
  belongs to the 5402 commit fence; the gate covers every *next* request.
- Third-party authority currency checks (`CurrentVerifier`, `CurrentQualifier`, owner lists, etc.)
  still read config only; they should consult `ICurrentMembershipResolver`/persisted state (5402).
- Invitation, activation, close/reopen, expiry worker, identity rebind, person link, service
  accounts, per-session listing/revoke and preference routes of 52.02 G are not implemented.
- Free-text reasons are not stored (closed reason codes only) pending a privacy decision.
- Config grant changes after import (new vessel grants/role/company) are fail-closed until a
  future audited grant-sync command; dedicated `ACCESS_LIFECYCLE` audit reason code + i18n.
- UI for membership administration is not part of this package.
