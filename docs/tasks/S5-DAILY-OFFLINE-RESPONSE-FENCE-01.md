# Daily enrollment response fence — S5-SOURCE-01 P1

DEV097–099 / T-OPS2-001–003. Independent source review found that a request could decrypt a retained conflict, wait for its success audit, and still return private values after a second HTTP request committed Revoke/KeyLost. The final check reused the originally loaded enrollment while only refreshing actor/vessel scope.

[DailyOfflineEndpoints.cs](../../backend/Poseidon.Api/DailyOfflineEndpoints.cs) now resolves a fresh trusted tenant context outside the request's Serializable snapshot. One fresh enrollment/vessel statement binds tenant, actor, vessel, kind, record, enrollment, device/key identity, public-key binding, challenge, source/schema/policy/authority digests, immutable base and retention boundary. Private export/replay also requires current policy/rights, non-revoked state and unexpired retention. Conflict/history repeat this check after success audit. Receipt recovery also audits and checks the fresh grant before returning its already committed outcome.

New captures require a live capture lease before commit; an expired capture lease still permits exact existing receipt recovery within valid retention and unchanged current policy/authority/key context. Pending key registration compares the originally loaded public key before commit and the committed key afterward, avoiding self-denial. Renew can start from an expired lease within retention, but its returned capture context requires the renewed lease. Revoked/lost/expired-policy cleanup remains current-owner metadata only; it never exports protected base/conflict values.

Post-commit enrollment/context/receipt responses use a separate withholding path: concurrent revocation or unavailable final audit/database checks return HTTP503 command_outcome_withheld and withhold the payload. They neither reclassify the commit as rollback nor roll back the completed transaction. Pre-commit revocation fails403 and disposal rolls back pending report, revision, outcome and write audit. No policy, old context, provider or operator configuration is broadened or activated.

[DailyOfflineResponseFenceTests.cs](../../tests/Poseidon.Api.Tests/DailyOfflineResponseFenceTests.cs) authors deterministic real PostgreSQL audit-wait interleavings for Conflict/History with both Revoke and KeyLost; fresh-commit and existing-receipt withholding; pre-commit rollback after an actual second revocation request; and capture-lease/retained-receipt separation. Existing key-bind/renew cases remain relevant. These sources have not run. No tests/build/typecheck/lint/generation/browser/provider/gate execution occurred; native evidence, acceptance and historical receipts remain unchanged.
