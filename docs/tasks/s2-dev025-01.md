## Acceptance criteria

- **DEV025-AC-01** Skip link is the first Tab stop, visible on focus, and moves focus to the page `main`.
- **DEV025-AC-02** Landmarks: exactly one visible `main` and one banner; repeated navigation landmarks have distinct names; ids unique.
- **DEV025-AC-03** Every visible shell control (incl. icon-only buttons) has an accessible name.
- **DEV025-AC-04** Modal dialogs (theme builder, vessel chooser, search, draft confirm): focus starts inside, Tab/Shift+Tab stay inside, the background is inert, Escape closes and focus returns to the trigger; `tabindex=-1` samples are never in the Tab cycle; no `inert` remains after close.
- **DEV025-AC-05** Live regions are not nested.
- **DEV025-AC-06** 320 CSS px (en, ar): no horizontal page scroll; drawer opens as a modal navigation anchored to the inline-start edge (right in Arabic), Escape returns focus to the menu button; appearance popover stays inside the viewport.
- **DEV025-AC-07** ≤767 px with a verified context: a summary button whose accessible name holds workspace, company, vessel, mode, role and connection; `aria-expanded`/`aria-controls` disclose the details; the polite live summary is only visually clipped; no summary while the context is unverified (errors stay visible); the switch action stays visible.
- **DEV025-AC-08** Form errors: fields carry `aria-invalid` + `aria-describedby`; on submit focus moves to an error summary whose entries link to the fields; the summary is not a live region.
- **DEV025-AC-09** 200 % zoom equivalent (640×400): no horizontal scroll and the top bar is not sticky. Where it is sticky (1280×800, 390×844): `scroll-padding-top` ≥ its measured height and reverse Tab navigation through scrolled content never leaves a focused element under the bar.
- **DEV025-AC-10** Shell contrast in every built-in palette and builder combination, light and dark: text pairs ≥ 4.5:1; the colour each shell focus indicator actually consumes (parsed from the stylesheets, incl. the portal-rendered theme builder) ≥ 3:1 on every shell surface; protected token values are read from `design-system.css`; the context bar uses tokens only.
- **DEV025-AC-11** `prefers-reduced-motion: reduce` disables non-essential animation on every surface, including portals.

## Independent QA follow-up (verdict FAIL → fixes)

| QA finding | Root cause | Fix |
| --- | --- | --- |
| Q1 AC-10 false claim: theme builder focus outlines used the palette/builder `--ring` (51/106 palette × mode combinations < 3:1, emerald light 2.59:1). | `ThemeBuilder` portals to `<body>`, outside `.product-shell`, where `--ring: var(--focus-ring)` was set; the contrast test hand-copied token values and only checked `--focus-ring` pairs, never what the outlines consumed. | Shell focus consumers (`appearance-controls.css`, `LanguageSelector.css`, `enterprise.css` field border, `workspace-role-navigation.css`) use `--focus-ring` directly; `design-system.css` protects `--ring` on `.product-shell, .theme-builder-backdrop, .theme-builder, .appearance-controls`. `shell-contrast.test.ts` now parses protected token values from `design-system.css`, parses every focus rule of the shell stylesheets, resolves the token each consumer uses (`--ring` only counts as protected inside a parsed protected scope, whole-class match) and checks it ≥ 3:1 on background/card/sidebar/muted/popover for 3 palettes + 50 builder combos × light/dark; a regression case proves the old unscoped rule fails. Literal focus colours are allowed only on a component with its own fixed surface (vessel chooser `#245fba` on `#fff`). |
| Q2 Flaky keyboard journey (60 Tab presses + 60 evaluates, 25–40 s). | Unbounded per-step round trips under load. | One evaluate collects the expected stop list (visible, enabled, tabindex ≥ 0, one stop per radio group); 4 bounded forward steps, then Tab from the last stop → first and Shift+Tab from the first → last. Skip link, inert background and focus return kept. |
| Q3 AC-09 vacuous at 640×400 (bar not sticky, loop asserted nothing). | Test only exercised the non-sticky branch. | 640×400 now asserts the bar is not sticky. New 1280×800 and 390×844 tests require `position: sticky`, `scroll-padding-top` ≥ bar height, inject test-only focus probes so the page scrolls, Shift+Tab through them and assert no focused probe starts above the bar bottom, the page scrolled and probes reached the bar edge (< 120 px). |
| Q4a Collapsed context details clipped but exposed (double reading). | Details are only visually clipped so the live region keeps announcing. | Decision: keep `.context-live` exposed (context-switch announcement, 65.03 paragraph 48 + DEV-021 live region). While collapsed on a narrow screen (`matchMedia('(max-width: 47.9375rem)')`, same breakpoint as the CSS) the duplicated workspace name is `aria-hidden`. Trade-off: a virtual-cursor reader can still hear company/vessel/mode/role once in the summary name and once in the clipped live region; accepted until a real AT pass decides otherwise. |
| Q4b Radio groups counted as many tab stops in `trapTab` / `focusableTargets`. | Every radio input was a stop. | A named radio group is one stop (checked radio, else first), matching the browser; `trapTab` treats any radio of the first/last group as that edge. |
| Q4c Undocumented limits. | — | `inertOutside` JSDoc documents the snapshot limitation (nodes inserted outside the modal after activation are not inert). `design-system.css` documents the reduced-motion iteration-count rule (every animation runs once; loading state must not rely on motion). |
| Q4d 320 px test skipped the Arabic role part. | `if (!part.startsWith('KURGUSAL'))` filter. | Asserts workspace, company, vessel, all roles (catalogue labels exist in TR/EN only; Arabic shows the EN label) and every rendered detail part (company, vessel, mode, role, connection) is in the summary name. |
