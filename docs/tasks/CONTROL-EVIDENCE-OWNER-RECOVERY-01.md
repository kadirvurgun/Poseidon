## Corrective behavior

[Owning controller](../../frontend/src/product/use-control-evidence-recovery.ts) binds actual actor/tenant to vessel/kind and captures the complete command envelope: nullable original server resource ID, method/action, exact serialized body, UUID idempotency key and expected revision. New head IDs are server-generated. No client body UUID or new API route is invented.

Protected reads fetch an actual session before/after the owning read. Send/retry fetches actual original owner, current read/write capability/visibility, then the original owner again for fresh CSRF. The original route/body/key remain unchanged. A previously UNKNOWN command survives every later400/401/403/404/409/503, timeout or read failure; later denial never establishes rollback of an earlier lost response. No local Discard, new key, implicit resend or parent navigation abandonment can erase it. Explicit **Retry source read** can restore only current original-owner visibility and exact retry. Permanent relationship/scope denial remains unresolved for genuine reconciliation.

[Receipt binding](../../frontend/src/product/control-evidence-api.ts) compares actual returned content/file/pins/lifecycle/revision with the captured command. It recognizes only actual backend normalization: known nullable contract fields, GUID identity casing, unordered immutable pin sets, and declared instants at100ns precision with equivalent offsets. It preserves false/null, units, literal source text, complete target versions and checksums. These comparisons never rewrite frozen wire bytes.

Known server identity is hydrated before optional reads. A failed list/versions read leaves that confirmation read-only and never creates another POST. Existing `/controls/{id}/versions` or `/evidence/{id}/versions` is used; no GET `/{id}` is fabricated. Versions can expose an older visible revision with a current editing head token. Therefore the controller also resolves the visible current row through the existing current-list route, with bounded25-item paging through the backend's100000-offset range, and cross-checks ID/revision/hash/token. A hidden, changed or unconfirmed current projection stays read-only; it is never a new draft. The bound is an engineering query budget, not a production/legal rule.

Original historical receipt bytes remain valid after a newer edit. The client does not compare a frozen old editor token with the newer head before replay or require fresh current qualification that the backend does not require before receipt recovery. After confirmation, deliberate local reset uses a newly fetched original-owner session and an established current owning read to resume editing the **same** server ID/current revision. Unsent local changes can be removed with fresh owner proof; known selected IDs are retained while current visibility is re-established. UNKNOWN is always immutable.

Own data/fields/history/pickers are withdrawn on current owner/access/source-proof loss. Render scope, mounted/abort refs and immutable command refs fence late responses. Source acknowledgment captures its owner/context/edit epoch and cannot apply after field edits, scope change, command capture, known receipt or unmount. The existing synchronous HRO review refs/acknowledgment generation are preserved and passed as an additional live guard; stale ancestor callbacks cannot unmount Human UNKNOWN. Parent `onDirty/onSaving` aggregation carries both own and human barriers. The Human controller stays mounted outside the own private projection gate, and is inert during an active owning mutation/local reset. Sibling VesselFiles source and its own transport contract remain unchanged; its container is inert while protected recovery is in progress. No private browser persistence is added.

## Backend semantics preserved

[ControlEvidenceEndpoints](../../backend/Poseidon.Api/ControlEvidenceEndpoints.cs) checks live write/scope/CSRF, owner eligibility, immutable requirement/source/rule relationships, linked visibility, actual ordinary clean file bytes and typed owning context before/within receipt lookup. Fingerprints bind kind + nullable ID + vessel + action + received JSON. Receipts remain tenant/actor/key scoped. Reauthorization and audited EF head/revision/link/receipt commit are unchanged.

Full qualified submission/acknowledgment/role admission is in the fresh non-save branch **after** replay. Do not copy Human RECORDED replay policy into ordinary Control/Evidence commands. Incomplete nullable drafts, source/file pins, typed owning inputs, DRAFT/SUBMITTED/COMPLETED, UNVERIFIED and UNKNOWN retain their meanings. File existence, completion, verification, effectiveness, source admission, human signature and permits remain separate. No new authority/approval is supplied.
