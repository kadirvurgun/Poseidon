## Boundary

OUT: full finance/general ledger/AP/AR/payment/accounting, payroll, RFQ/supplier/purchase-order lifecycle, full warehouse/inventory ERP and charter-party transaction management. IN: source-governed technical requisition and critical spare reference context with provenance; existing technical records and explicitly scoped critical stock are not reclassified as full ERP. External amounts/finance transactions do not fit this v1 reference envelope. Future approved cost projections need their own typed contract, never an implicit financial command.

`ErpReferenceBoundary` and closed JSON schema accept only bounded primitive reference fields. Version, message/reference/tenant/vessel identifiers, exact configured source/version/kind, positive safely representable source revision and ISO source time are required. Optional external status/PO/vendor/cost references remain opaque. Missing status stays null; stale/future observations retain distinct freshness and never become fulfilled/approved/ready. No arbitrary JSON/extensions/free-text/credentials/caller actor or permissions are accepted. Unknown/duplicate/case-variant/nested/oversized fields fail closed without echoing private inputs. Values are not URLs to fetch or claims to trust.

The pure decoder is NOT an authorization handler. A future consumer must first reauthenticate the trusted integration principal, current tenant/vessel/object and allowed source/version/purpose, constructing expected context from those authoritative records, never the request. Source-version changes require explicit reconciliation; safe client integer limits avoid revision loss in JSON consumers. Reconciliation distinguishes same-message recovery, older source data, changed binding and same-revision material differences. A changed message ID cannot hide a same-revision conflict; no last-write-wins. Future persistence must use ordinary audited SaveChanges, tenant enforcement and atomic immutable receipt/provenance; current permission revocation is checked before prior receipts. No such runtime persistence/outbox/HTTP/provider adapter is claimed here. No delivery/financial/safety/legal decision, credential, outbound call or invented provider status is created.
