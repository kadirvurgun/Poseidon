# Hourly quota watcher (OPS-HOURLY-01)

Source: user task OPS-HOURLY-01, 2026-10-31; account worker foundation imported from reviewed `e37ac0d`. This is a local automation subpackage awaiting independent QA, not a sprint acceptance or a running unattended development service.

`py scripts/codex_watch.py once` reads account and rate-limit metadata for Esra Pro and Kadir Plus using the existing app-server adapter. It makes no model calls. `py scripts/codex_watch.py --loop` repeats hourly using monotonic time, with interruptible waits and no catch-up bursts. The snapshot is atomically replaced at `.runtime/account-workers/quota.json` with UTC timestamp, next check, sanitized profile metadata and selection. A failed check is unknown, never ready; an old snapshot is informational and never authorizes dispatch. Credentials are neither read nor copied by these scripts. The existing worker environment removes ambient API keys.

Policy: Esra is selected first when its authenticated plan and its own known quota windows are eligible. Kadir Plus is eligible only using its independently authenticated profile and its own quota windows. Any window at **85% or higher** is reserved; 100% is exhausted. Invalid, missing or unavailable usage is ineligible. These percentages are within each plan's windows, not equivalent token capacities across plans. Selection does not guarantee that quota will remain available during a task. No resets, purchases or unlimited account rotation are performed.

`--task C:\absolute\trusted-task.md` explicitly authorizes one bounded `Workers.run`. Treat the task file as trusted code instructions: the existing worker uses full native access in its isolated worktree, with its configured timeout. The watcher takes a global lock, requires both profile checks to be known, refuses existing job directories or a dispatch receipt, passes only the selected account, and rechecks reserve eligibility under that account's lock immediately before execution. A quota response cannot trigger automatic fallback. A receipt is written before dispatch so restarts cannot duplicate the task. `blocked`, `needs_review`, quota waits, interrupted dispatches and uncertain termination require coordinator review; the watcher never accepts, merges, publishes or automatically resumes them. The watcher does not implement a durable multi-task queue. Separate manual workers must also be coordinated by the parent; its lock serializes watcher invocations, not every possible external launcher.

Do not delete stale locks or `.runtime/account-workers/dispatch.json` automatically. Check the process tree and job state first. Uncertain termination retains locks; Windows `taskkill` itself has a 10-second timeout. Task files, worktrees and existing worker job state are local artifacts and may contain task content; quota snapshots do not contain raw errors, identities or prompts.

After independent QA the parent may inspect `scripts/install-hourly-watch.ps1 -Preview`, then run the installer explicitly. It constructs the separate task **Poseidon-HourlyQuota**, using the current user's Interactive/Limited principal, no password, a hidden `pythonw.exe` process, absolute executable/working paths and a quoted script argument. The hourly task runs `once`, has IgnoreNew/StartWhenAvailable and a five-minute execution limit. It performs metadata checks only; installation does not enable model dispatch. The installer does not start the task. `-PythonPath` can specify the installed Python executable when launcher discovery is unsuitable. No scheduled task was registered or started as part of implementation.

The host must be awake, Windows running, and that user logged in with usable account authentication. Locking the desktop can preserve the interactive session; logging out does not. This task does not wake a sleeping host. StartWhenAvailable can run a missed check when the session is available; it does not provide continuous coverage during sleep, shutdown or logout. The next-check timestamp is a target, not evidence of execution. Inspect real task history and snapshots after installation; a verified queue, independent QA and target-commit CI remain separate gates before any claim of unattended development.

Acceptance/traceability: `scripts/test_codex_watch.py` covers OPS-HOURLY-01 metadata snapshots, redaction, busy/uncertain locks, reserve and account ordering, durable single dispatch, monotonic scheduling and mocked PowerShell task construction. Additional `scripts/test_codex_accounts.py` regressions cover single-account no-fallback, fresh reserve checks under lock and bounded taskkill. Run `py -m unittest discover -s scripts -p test_*.py -q`; tests use fake metadata/time/processes and scheduler cmdlets, with no real model/auth/network requests. Parent owns project-status files and phase reports.

Protocol reference: [official Codex app-server documentation](https://learn.chatgpt.com/docs/app-server) describes `account/read` and `account/rateLimits/read`; the watcher reuses the existing adapter without starting a model turn.
