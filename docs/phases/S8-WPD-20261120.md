## Behaviour

- **DEV-087**: plan aggregate with tug roles (position, towing method, exactly one coordinating tug, towline source, connection point,
  links to the tug's own DEV-085 Towline/EmergencyRelease items), information exchange, limits (closed parameter list with a
  server-defined unit; value and source are plan inputs, no defaults), communication plan (primary/standby channel, language, lost
  communication procedure), emergency release (procedure, ordered by), contingency (closed scenarios), snap-back zone controls
  (zones marked: unknown/yes/no + controls). Drafts may be incomplete (POL-DEFAULT-01); submit lists every missing section and requires a
  current DEV-083 proposal for each planned tug. Approval/return is a Master/Tug Master human record from a server-provisioned
  `TugOperationsAuthority` on the coordinating tug, bound to the content hash; the approver is never an author or the submitter.
  Amend opens a new draft revision. A request revision change after approval makes the plan stale.
- **Readiness communication**: `communication` is PASS only for a current approved plan covering the tug and matching the request
  revision (`ApprovedTowagePlanCommunication`); otherwise UNKNOWN with a reason. Weather stays UNKNOWN; the engine never issues GO.
- **DEV-088**: briefing with conditions confirmed at the briefing, hazards, preventive and mitigating barriers, stop-work authority and
  triggers, emergency arrangements, linked DEV-105 risk assessment (risk state READY/ATTENTION/BLOCKED/REVIEW_REQUIRED) and participants.
  Issue requires completeness, the current approved plan and an approved risk assessment, and pins both revisions; it is recorded by the
  coordinating tug's appointed Tug Master/Master. Each participant ACKs or DISPUTEs (with reason) the exact issued revision for themselves.
  New readiness category `briefing`: missing/not issued/plan or risk changed/pending or disputed acknowledgement is FAIL, so an incomplete
  briefing blocks READY; hidden risk is UNKNOWN.
- **DEV-107**: read-only fleet projection over the actor's scoped vessels: submitted tug jobs (with plan, briefing, linked risk and live
  DEV-084 crew/equipment readiness for active proposals) and risk assessments of high-risk work types (MAINTENANCE/unset → UNCLASSIFIED,
  never dropped). Fleet (company), vessel and work-type filters; risk/permit/barrier/crew/equipment states; owner/due (unresolved due stays
  null); Why drill-down of every dimension; fixed NextAction priority. No aggregate score: rows with any critical blocker sort first.
  Permit-to-work has no source → permit UNKNOWN, so NONE is never produced. Barrier health has no source → UNKNOWN (FAILED only for a
  failing emergency release check). New permission `hse.high_risk_work.read` (50.01 paragraph 907).
