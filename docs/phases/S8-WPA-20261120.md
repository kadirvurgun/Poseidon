## Delivered behavior
- **DEV-052** Equipment criticality is a closed vocabulary `CRITICAL|IMPORTANT|STANDARD` (null = `UNKNOWN`, treated like CRITICAL by safety consumers); other text is refused (400). Maker/model/serial/location/parent stay versioned via `AssetRevision`; a cycle is refused with explicit `hierarchy_cycle`; vessel scope unchanged. Tree shows a criticality marker; the editor uses a select.
- **DEV-053** Plans may read meter/condition inputs from a measurement point (`measurementPointId`, `triggerOn` WARNING|ALARM). Due calculation stays deterministic (culture/time-zone/month-end tests); the plan projection carries `assetCriticality` and the postponement overlay. Invalid postponements are refused with explicit codes and audited (SecurityEvent `MaintenancePostponementCommand`).
- **DEV-108** `MeasurementPoint` (kind RUNNING_HOURS/RPM/PRESSURE/TEMPERATURE/VIBRATION, closed unit per kind, range, precision 0-6, MANUAL/DEVICE source, optional parent counter) with append-only revisions; append-only `MeasurementReading` history (exact lexical decimals, evidence file reference, source reference). Running-hours counters are chronological and never decrease (`counter_decreasing`, `reading_out_of_order`). Parent -> sub-counter delta propagation creates `PROPAGATED` readings citing the parent reading; sub counters without a baseline are skipped and reported. Thresholds are tenant-configured (`MaintenanceObservations:MeasurementPolicies`); none -> `UNCONFIGURED` band and `ReviewRequired/MeasurementPolicyUnconfigured` plan, never NORMAL/NotDue. Band evaluation follows 59.04 p106 (inclusive, heavier wins); stale reading -> `MeasurementStale`.
- **DEV-109** The always-denied postpone route is replaced by request -> decision: reason, requested deadline > original due, optional risk review (risk assessment id), work order and defect id references (read-only, same vessel), criticality frozen from equipment. Decision APPROVE/REJECT by a different person (`separation_of_duties`), needs the tenant policy (`MaintenanceObservations:PostponementPolicies`; unconfigured -> 422 `postponement_policy_unconfigured`), max extension measured from the first original due (`postponement_extension_exceeds_policy`, AT-034), an approved risk review for CRITICAL/UNKNOWN (`risk_review_required`) and an unchanged plan revision/due (`plan_context_stale`). The original due date is never changed. Readiness impact: CRITICAL/UNKNOWN -> `REVIEW_REQUIRED` (also added to the tug readiness consumer), other approved -> `CONDITIONAL_DEFERRED`, never ready. DB CHECKs forbid a decision by the requester and an approval without policy/within-limit extension.
