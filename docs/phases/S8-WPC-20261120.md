## Delivered behaviour

- **DEV-055 critical defect lifecycle (T-S8-004).** `DefectLifecycle` head + append-only `DefectLifecycleRecord` attached to the
  existing owning defect declaration (declaration endpoints unchanged). Stages DETECT → ASSESS → SAFEGUARD → ACTION → VERIFY →
  EFFECTIVENESS → CLOSED, eight audited commands under `/api/v1/defects/{id}/lifecycle/*?vesselId=`.
  - A defect is critical when the declared **or** assessed criticality is Critical (conservative, ISM 10.3). Critical: no corrective
    action without an ACTIVE safeguard/restriction; the last active one cannot be lifted before effectiveness; closure requires a
    recorded safeguard, VERIFIED verification of the latest action, EFFECTIVE effectiveness and no expired temporary measure.
  - Temporary measures require a future UTC expiry; expiry is evaluated with the server clock on every read (no scheduler); an expired
    measure is a blocking alert and a closure blocker until renewed or lifted by a human.
  - Separation of duties: verifier, effectiveness assessor and closer must not be an action owner; each needs its own permission
    (`defect.verify`, `defect.effectiveness`, `defect.close` = return-to-service authority). Failed verification/effectiveness returns to
    ACTION; a declaration edit after verification blocks closure.
  - S7 tug readiness adapter: a defect is not open only when a human CLOSE record exists for the current declaration revision
    (`DefectLifecycleReader.ClosedRevisions`, `TugReadinessAssessor.Defects` → Pass `DefectClosed`).
- **DEV-103 Service & Engineer Report (T-PMS2-001).** `ServiceReport` head, immutable `ServiceReportRevision`, `ServiceReportVerification`.
  Provider, engineer, date, scope, work, parts, measurements/tests, defects found, recommendations, next action due; pins to current
  equipment/work-order/defect revisions in the same vessel (STALE shown, never re-pinned silently) and clean secure-file transports
  (`TRANSPORT_ACCEPTED_UNVERIFIED`). DRAFT → SUBMITTED (422 `service_report_incomplete` with missing list) → VERIFIED/RETURNED by a
  non-author (`service.report.verify`); AMEND opens a new draft while the verified revision stays readable.
- **DEV-056 PMS Command Center (T-S8-005).** `GET /api/v1/pms/command-center?vesselId=`: critical overdue, due/overdue/review jobs
  (maintenance projection), open work orders and critical spare gaps (read-only `IPmsWorkOrderStateSource` / `IPmsSpareGapSource`,
  default **UNKNOWN** until WP-B wiring), condition alerts (defect lifecycle). Each item has a Why chain; healthy rows are counted
  as quiet; stale readings are marked; forbidden sections are ACCESS_REQUIRED; readiness is advisory and never clean while a source
  is unknown.
- UI: lifecycle panel in the defect workspace, `/app/pms-command-center/{vessel}`, `/app/service-engineer-report/{vessel}?id=`;
  menu/lens/search/vessel-switcher wiring; all strings in 17 locales.
