Checklist rule: an item is SATISFIED only by an active human link to a real existing record of the same tenant that the
server verified (exists, tenant, record type allowed for the item, vessel = program ship/tug per item area, provenance not
`SyntheticUnverified`, audit trace where required, UAT run ATTESTED and same mode, program-owned records of the same
program). Links are re-probed on every read (deleted record -> LINK_INVALID). Links are made only by `ActorKind=Human`
with `pilot.program.record`; AI/automation get 403 `human_actor_required`. Withdrawal is append-only (once).

Week close and program decision: `pilot.program.decide` + a current server-provisioned `Membership.PilotGateAuthorities`
Product Owner appointment (DEV-075 pattern). Bound to the week/program content hash and lineage sequence (stale -> 409
`week_stale`/`program_stale`), append-only, snapshot of closed codes. ACCEPTED only for READY_FOR_HUMAN_CLOSE (all items
satisfied, no P0 open/pending/late/overdue) — DB CHECK; NOT_ACCEPTED always recordable; no close before the week starts.
EXPAND only when every week is ACCEPTED, all value metrics measured, both UAT gates PASS, defect data known with no open
critical/unassessed defects and P0 = 0 — DB CHECK; CONTINUE/FIX/STOP always recordable. Separation of duties (follow-up 21.11.2026): a week closer
must not have authored an active link of the week, feedback of the week or linked from it, or a measurement linked from it
(W4, which uses the value readout: any measurement the readout uses); the program decider must not have authored any active
link or any measurement the readout uses or a link references. Checked inside the SERIALIZABLE transaction and enforced again
by the PostgreSQL trigger `pilot.guard_pilot_duty()` (migration `20261124090000_PilotProgramDutySeparation`). Synthetic programs can be
neither closed nor decided. The engine only recommends (READY_FOR_HUMAN_CLOSE / EXPAND_ELIGIBLE_PENDING_HUMAN_DECISION).

## What the audit-trace check proves (and does not)
`RequiresAuditTrace` checks that a `User`-attributed write audit event exists for the linked record (its ResourceId or
EntityId), at link time. It proves that **a human wrote the record**. It does **not** prove that the record, the flow or
the pilot step is complete, correct or verified. Where the source AC says the flow must be *completed* (DEV-077 W2 work
order, defect/safeguard, departure review, offline/reconnect), the item additionally requires the owner module's completion
state (`RequiresCompletion`, live on every read). Other items (e.g. DEV-078 "at least one event flow") rest on the
human-written trace only; the UI states this next to each traced item. Week acceptance remains the Product Owner's human
judgement of the linked evidence.
