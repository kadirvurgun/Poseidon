## Behaviour

- **DEV-060 capture**: type, occurrence (EXACT time / DATE_ONLY / UNKNOWN + reason; future rejected), operation context, location, summary,
  narrative, immediate action (YES/NO/UNKNOWN + text), reporter severity *claim*, evidence pins (CLEAN secure files of the same vessel;
  optional). Drafts may be incomplete (POL-DEFAULT-01); submit returns 422 `safety_event_incomplete` with the missing list. UNKNOWN is never
  turned into No. Only the reporter edits/submits/withdraws; a submitted report cannot be withdrawn. Drafts are visible only to their reporter.
- **Protected mode**: `CONFIDENTIAL` keeps the reporter only in `hse.SafetyEventIdentities` (vault). The event head has no reporter, history
  revisions authored by the protected reporter carry no actor id, and every general read shows `reporter.actorId = null`. The vault is read only
  through `POST /identity-access` (`hse.safety_event.identity.read`, human, closed purpose + reason, append-only access record). With
  `IN_APP_FOLLOW_UP`, submission returns a 256-bit follow-up token exactly once (only its SHA-256 is stored); `GET /follow-up` and
  `POST /follow-up/messages` take the token in the `X-Safety-Follow-Up` header, show only REPORTER_SHARED messages and never write an actor
  receipt. `ANONYMOUS` returns 422 `anonymous_channel_unavailable` (the unauthenticated public gateway of 61.01 §11 is not configured).
- **Offline capture (DEV-033 protocol)**: per actor+vessel enrollment, operator policy (`SafetyEventOffline`, every part classified
  RestrictedOperationalDraft, else UNAVAILABLE_POLICY), P-256 key proof, encrypted IndexedDB queue, signed replay that creates exactly one NAMED
  DRAFT (`Origin=OFFLINE`); same command+digest returns the stored outcome; renew/revoke/lost/cleanup lifecycle. Submission and all decisions stay online.
- **Triage**: human-only (`hse.safety_event.triage`), never the reporter; severity UNASSESSED..CRITICAL and investigation need YES/NO/UNKNOWN
  as a human classification (`severityPolicy = UNCONFIGURED`), or RETURN to the reporter. Re-triage allowed while TRIAGED.
- **DEV-061 investigation**: one per event; scope, contributing factors (FACT/ALLEGATION/INFERENCE/UNRESOLVED × category), human root causes
  linked to factors (UNVERIFIED/SUPPORTED/CONTRADICTED/INCONCLUSIVE), barrier analysis (PREVENTIVE/MITIGATING × FAILED/MISSING/DEGRADED/WORKED/
  UNKNOWN), uncertainties, evidence. Submit needs scope, ≥1 factor, ≥1 barrier and a root cause or an explicit uncertainty. Independent review
  (APPROVE/RETURN/REJECT) by someone who is not an author, the submitter or the reporter; REJECT returns the event to TRIAGED and the
  investigation is revised into a new draft. No root cause is ever derived by the system.
- **Actions**: corrective/preventive with owner (server-provisioned tenant member), due date (not past; overdue shown), links to approved root
  causes/barriers, optional follow-up of a NOT_EFFECTIVE action. Steps: COMPLETE (owner), VERIFY (human, ≠ owner/completer, rejected work
  returns to OPEN), EFFECTIVENESS (human, ≠ owner/completer/verifier; EFFECTIVE/NOT_EFFECTIVE final, INCONCLUSIVE reviewable again).
- **Closure**: human-only by an independent reviewer (not reporter, not investigation author). Blockers (cannot be bypassed): investigation
  need UNKNOWN/required, investigation not approved, failed/missing/degraded barrier or non-contradicted root cause without an action, action
  not verified, effectiveness not reviewed/inconclusive, NOT_EFFECTIVE without follow-up. Closure is a separate record next to event
  effectiveness (EFFECTIVE/NOT_EFFECTIVE/INCONCLUSIVE/PENDING/NO_ACTIONS): Closed ≠ Effective.
- **Read contract for other packages**: `ISafetyEventBlockerSource.ForVessel(db, actor, vessel, now, ct)` → `SafetyEventBlockerSnapshot`
  (`BLOCKERS_PRESENT` for open HIGH/CRITICAL, `REVIEW_REQUIRED` for untriaged/returned/UNASSESSED, `NO_OPEN_HIGH_SEVERITY_EVENT`, `UNAVAILABLE`
  without `hse.safety_event.read`; never READY; coverage `SeverityPolicyUnconfigured`). Shared draft DTO: `Poseidon.Domain.SafetyEventDraftFields`.
