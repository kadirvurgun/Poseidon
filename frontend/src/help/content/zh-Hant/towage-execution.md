## 本頁用途
執行控制台以時間軸的形式記錄已提交拖船任務的**實際執行**：開始、觀測、**暫停 / 恢復 / 中止 / 完成**操作以及之後的查證。它回答的問題是：「作業何時開始？拖纜何時連接和釋放？記錄了哪些觀測？作業處於什麼狀態？紀錄是否已查證？」開始和狀態轉換是執行拖船上的拖船船長或船長的人工紀錄；控制台絕不簽發 GO。

## 誰使用本頁
- **拖船船長 / 船長：**開始作業，並記錄開始/暫停/恢復/中止/完成時間軸及其證據（13.03 §3）。
- **查證人（具有執行查證權限的人員）：**查證已完成或已中止的紀錄，或駁回其查證（13.03 §1）。
- **拖船作業協調員 / 岸上營運：**追蹤已完成任務的證據完整性和歷史；他們不能開始或中止作業（13.03 §7）。

## 開始之前
- 從**拖船作業**開啟拖船，並從**選擇已提交的拖船任務**中選擇任務。
- 要開始作業，以下各項都必須為目前有效：拖船的有效指派、已核准的**拖帶計畫**（拖船必須在計畫中）、已發布且已由每位參與者確認的**拖帶風險與簡報**，以及**作業就緒關卡**上與目前評估綁定的**GO**紀錄。
- 開始和狀態轉換需要伺服器中已記錄的該拖船**任命**（拖船船長或船長）。

## 操作步驟
1. 在**開始條件**區段，閱讀每艘拖船的**就緒決定**和**阻礙項目**。
2. 如果沒有阻礙項目，請以船上被任命人員的身分閱讀確認文字，選擇您的**任命**，可選擇輸入**開始位置**，然後按**開始作業**。
3. 執行開啟後，追蹤**狀態**、**查證**以及帳冊欄位（拖纜已連接/已釋放、觀測到的最大拖力、通訊、絞車、緊急釋放試驗、有效分鐘數）。
4. 在**記錄觀測**中，選擇觀測類型（例如拖纜已連接、拖力、通訊檢查、天氣、絞車狀態、緊急釋放試驗、位置、證據、備註），輸入數值並按**記錄觀測**。
5. 在**拖船船長操作**中，選擇**操作**（暫停、恢復、中止、完成），並輸入您的**任命**和**理由**。中止和完成需要至少 20 個字元的理由，並會開啟**結束位置**欄位；沒有結束位置時不接受完成。
6. 如果列出了**完成阻礙項目**，請將其清除；例如，如果拖纜仍處於連接狀態，請先記錄其釋放。
7. 作為查證人，寫下理由並按**核驗紀錄**或**駁回核驗**。
8. 在**時間軸**中按順序查看每個事件。

## 狀態含義
- **進行中 / 已暫停 / 已完成 / 已中止：**作業狀態。已完成並不表示紀錄已查證。
- **待處理 / 已查證 / 已駁回：**查證狀態。已完成 ≠ 已查證；查證是另一人的紀錄。
- **良好 / 中斷 / 通過 / 未通過 / 有條件 / 未知：**通訊、絞車和緊急釋放觀測的結果。未知表示沒有記錄任何內容；它絕不能代替「良好」或「通過」。
- **安全事件 — 未知：**此控制台不統計安全事件；不會得出「沒有事件」的結論。
- **GO（人工紀錄） / NO GO（人工紀錄）：**拖船船長或船長在就緒關卡上記錄的決定。

## 不能做的事 / 注意
- 岸上使用者、AI 和系統身分不能開始或中止作業。岸上指派絕不能推翻拖船船長在船上的安全決定（13.03 §7）。
- 只有被任命的拖船船長或船長才能暫停、恢復、中止或完成作業。作業進行期間始終可以中止。
- 開始或結束作業的人不能查證同一紀錄；查證在作業結束後進行。
- 帳冊只能附加；已記錄的事件絕不會被刪除或變更。
- 離線時不會傳送任何指令。觀測可以在**拖船離線作業**中排入佇列；開始、狀態轉換和查證仍需在線上進行。

## 發生問題時
- **出現「伺服器列出了缺漏或阻礙的項目。」訊息：**清除**阻礙項目**或**完成阻礙項目**中的代碼（例如計畫未核准、簡報確認待處理、GO 紀錄缺漏或不是目前有效的）。
- **出現「紀錄已變更或指令衝突。」訊息：**使用**重新載入最新版本**審核該紀錄。
- **出現「結果未知。」訊息：****重試**會再次傳送完全相同的指令。
- **未獲授權：**檢查您的角色、拖船和任命情境；必要時聯絡您的租戶管理員（13.03 §10）。
