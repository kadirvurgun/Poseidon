## 本頁用途
「試點 go/no-go 審查」頁面在一處顯示試點所需關卡的狀態、未關閉 P0 的數量和支援準備情況，並記錄被任命的產品負責人的 go/no-go 決定。它回答的問題是：「每個試點關卡是否都有證據滿足？是否已記錄人工決定？」頂部的提示適用：「僅為諮詢性審查。未知或延後的關卡以及未知或未關閉的 P0 會建議 NO-GO。只有被任命的產品負責人才能記錄決定。」

## 誰使用本頁
- **產品負責人：**閱讀審查結果，並附理由記錄 go/no-go 決定。作出決定需要目前的產品負責人任命。
- **支援 / 租戶管理員：**用證據參照標記支援和值班準備項目。
- 13.03 沒有為本頁定義另外的角色；適用租戶管理原則（最小權限、受控發布）（13.03 §9）。

## 開始之前
- 檢視需要租戶範圍讀取和試點關卡讀取權限。標記支援項目需要支援紀錄權限；作出決定需要決定權限以及伺服器上設定的目前產品負責人任命。僅有權限是不夠的。
- 只有人工帳戶才能標記支援或作出決定；任命必須與您目前的角色相符並在其有效期內。
- 關卡輸入來自其他頁面；例如，船舶 UAT 和拖船 UAT 關卡是根據**角色 UAT 記錄**頁面上已證明的執行計算的。
- 記錄需要即時連線；離線時被停用。

## 操作步驟
1. 在**試點關卡審查**中，閱讀建議（**諮詢性建議**）、**未關閉 P0** 數量以及關卡表：**關卡**、**狀態**、**來源**、**原因**。
2. 在**支援與值班準備**中，為每個項目選擇**狀態**，對**就緒**輸入**證據參考**，寫下**備註**並按**標記**。
3. 如果您是產品負責人，請在**記錄 go/no-go 決定**中選擇決定（**NO-GO**、**有條件 GO**、**GO**），在**任命**中選擇您的產品負責人任命，並寫下**理由**。對於**有條件 GO**，請填寫**條件（每行一條）**。
4. 按**記錄**。決定會連同其序號顯示在**產品負責人決定**中。
5. 按**重新整理**重新載入資料。

## 狀態含義
- **達到證據門檻（PASS）：**關卡的來源達到了證據門檻。這不是核准；由人作出決定。
- **未通過（FAIL）**、**未知（UNKNOWN）**、**已延後（DEFERRED）：**關卡未滿足。未知或延後的關卡絕不會被計為已通過，並會建議 NO-GO。
- **建議 NO-GO：**至少有一個關卡不是 PASS，或未關閉的 P0 數量未知或大於零。
- **符合 GO 條件；待人工決定：**所有關卡均為 PASS，且未關閉的 P0 為零。系統絕不會決定 GO；只有產品負責人才能記錄它。
- **未標記 / 就緒 / 未就緒：**支援項目最近一次標記的狀態。
- **目前 / 過時：審查已變更：**決定與作出決定時的審查綁定。如果審查之後發生變化，該決定會顯示為過時，需要重新考慮。

## 不能做的事 / 注意
- 「只有當所有關卡均為 PASS 且未關閉的 P0 為零時，才可能 GO。」否則 GO 選項被停用。
- 有條件 GO 需要與 GO 相同的狀態（所有關卡 PASS，未關閉 P0 已知為零）以及至少一個條件。當任何關卡未通過、未知或延後，或 P0 未關閉或未知時，不能記錄有條件 GO。NO-GO 始終可以記錄，且無需條件。
- 系統、AI 或自動化絕不會作出試點決定，也絕不會偽造關卡或簽署。試點關卡和決定都是人工紀錄。
- 您不能變更已記錄的決定；新的決定會以新的序號新增。

## 發生問題時
- **您沒有目前的產品負責人任命。決定為唯讀。**任命在伺服器上設定；請聯絡租戶管理員（13.03 §10）。
- **您無權存取這些記錄。**檢查您的角色和租戶範圍。
- **記錄已變更或已被使用。請重新載入。**在您作出決定期間審查發生了變化；請使用**重新載入**開啟目前審查。當關卡狀態發生變化導致不再允許該決定時，也會顯示此訊息。
- **結果不確定。重試將送出相同命令。**使用**重試**安全地重新傳送同一指令。
- **遭規則拒絕。**某個關卡已被延後。
- **不允許。**您的任命不是目前有效的，或您的帳戶不是人工帳戶。
- **服務無法使用。請重試。**如果問題持續，請向支援團隊回報關聯 ID、時間和操作步驟（13.03 §10）。
