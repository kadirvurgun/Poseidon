## 本页用途
“试点 go/no-go 评审”页面在一处显示试点所需关卡的状态、未关闭 P0 的数量和支持准备情况，并记录被任命的产品负责人的 go/no-go 决定。它回答的问题是：“每个试点关卡是否都有证据满足？是否已记录人工决定？”顶部的提示适用：“仅为咨询性评审。未知或推迟的关卡以及未知或未关闭的 P0 会建议 NO-GO。只有被任命的产品负责人才能记录决定。”

## 谁使用本页
- **产品负责人：**阅读评审结果，并附理由记录 go/no-go 决定。作出决定需要当前的产品负责人任命。
- **支持 / 租户管理员：**用证据引用标记支持和值班准备条目。
- 13.03 没有为本页定义单独的角色；适用租户管理原则（最小权限、受控发布）（13.03 §9）。

## 开始之前
- 查看需要租户范围读取和试点关卡读取权限。标记支持条目需要支持记录权限；作出决定需要决定权限以及服务器上配置的当前产品负责人任命。仅有权限是不够的。
- 只有人工账户才能标记支持或作出决定；任命必须与您当前的角色相符并在其有效期内。
- 关卡输入来自其他页面；例如，船舶 UAT 和拖轮 UAT 关卡是根据**角色 UAT 记录**页面上已证明的执行计算的。
- 记录需要实时连接；离线时被禁用。

## 操作步骤
1. 在**试点关卡评审**中，阅读建议（**咨询性建议**）、**未关闭 P0** 数量以及关卡表：**关卡**、**状态**、**来源**、**原因**。
2. 在**支持与值班准备**中，为每个条目选择**状态**，对**就绪**输入**证据参考**，写下**备注**并按**标记**。
3. 如果您是产品负责人，请在**记录 go/no-go 决定**中选择决定（**NO-GO**、**有条件 GO**、**GO**），在**任命**中选择您的产品负责人任命，并写下**理由**。对于**有条件 GO**，请填写**条件（每行一条）**。
4. 按**记录**。决定会连同其序号显示在**产品负责人决定**中。
5. 按**刷新**重新加载数据。

## 状态含义
- **达到证据阈值（PASS）：**关卡的来源达到了证据阈值。这不是批准；由人作出决定。
- **未通过（FAIL）**、**未知（UNKNOWN）**、**已推迟（DEFERRED）：**关卡未满足。未知或推迟的关卡绝不会被计为已通过，并会建议 NO-GO。
- **建议 NO-GO：**至少有一个关卡不是 PASS，或未关闭的 P0 数量未知或大于零。
- **符合 GO 条件；待人工决定：**所有关卡均为 PASS，且未关闭的 P0 为零。系统绝不会决定 GO；只有产品负责人才能记录它。
- **未标记 / 就绪 / 未就绪：**支持条目最近一次标记的状态。
- **当前 / 过时：评审已更改：**决定与作出决定时的评审绑定。如果评审之后发生变化，该决定会显示为过时，需要重新考虑。

## 不能做的事 / 注意
- “只有当所有关卡均为 PASS 且未关闭的 P0 为零时，才可能 GO。”否则 GO 选项被禁用。
- 有条件 GO 需要与 GO 相同的状态（所有关卡 PASS，未关闭 P0 已知为零）以及至少一个条件。当任何关卡未通过、未知或推迟，或 P0 未关闭或未知时，不能记录有条件 GO。NO-GO 始终可以记录，且无需条件。
- 系统、AI 或自动化绝不会作出试点决定，也绝不会伪造关卡或签署。试点关卡和决定都是人工记录。
- 您不能更改已记录的决定；新的决定会以新的序号添加。

## 出现问题时
- **您没有当前的产品负责人任命。决定为只读。**任命在服务器上配置；请联系租户管理员（13.03 §10）。
- **您无权访问这些记录。**检查您的角色和租户范围。
- **记录已变更或已被使用。请重新加载。**在您作出决定期间评审发生了变化；请使用**重新加载**打开当前评审。当关卡状态发生变化导致不再允许该决定时，也会显示此消息。
- **结果不确定。重试将发送相同命令。**使用**重试**安全地重新发送同一命令。
- **被规则拒绝。**某个关卡已被推迟。
- **不允许。**您的任命不是当前有效的，或您的账户不是人工账户。
- **服务不可用。请重试。**如果问题持续，请向支持团队报告关联 ID、时间和操作步骤（13.03 §10）。
