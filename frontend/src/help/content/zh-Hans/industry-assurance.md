## 本页用途
“行业保证”页面从工作簿导入油轮的 SIRE 2.0 检查结果，将变更提交人工审查，把发现项关联到安全措施，并记录现场证据。它回答的问题是：“这次检查的哪些发现项尚未关闭？哪些已关联措施？证据在哪里？”导入是草稿：每个变更的条目都由另一人接受。发现项保持未关闭且未经核验；本页绝不会关闭或核验它们。链条是发现项 → 措施 → 核验，核验和有效性是“安全事件与未遂事件”中针对措施的独立人工记录（13.03 §4, §8）。

## 谁使用本页
- **DPA / HSEQ：**将检查发现项关联到措施，并跟踪发现项 → 措施 → 核验链（13.03 §4）。
- **法规 / 保证用户：**管理列映射，准备或审查导入（13.03 §8）。
- **船长和船上人员：**为发现项记录现场证据（照片）。

## 开始之前
- 选择船舶。SIRE 2.0 仅适用于油轮。如果船舶档案中未声明船舶类型，导入保持**需要审查**。
- 读取需要检查读取权限。导入、接受导入、写入证据、关联发现项和编写映射都是单独的权限。关联措施还需要安全事件读取权限；记录证据还需要文件读取权限。
- 列结构是合成的；未使用获许可的 OCIMF 格式。
- 离线时只有照片采集会在此设备上排队；导入和决定需要网络连接。

## 操作步骤
1. **选择船舶**并检查**适用性**行。
2. 必要时，在**列映射**中输入**映射键**，每列写一行（表头=字段），然后按**另存为新版本**。
3. 在**准备导入**中选择**映射版本**、**检查编号**、**检查日期**和**工作簿（.xlsx）**，然后按**提交审查**。
4. 由另一人在**导入审查**中为每个变更的条目选择**接受**或**保留当前值**，写下至少 10 个字符的**理由**，然后按**接受导入**或**拒绝导入**。
5. 从**检查**列表中打开一次检查。审核**条目**和**发现项**。
6. 要将发现项关联到措施，请输入**安全措施 ID**并按**关联措施**。
7. 对于现场证据，请输入**媒体**、**干净文件 ID**、**文件修订**和**文件校验和（SHA-256）**，然后按**记录现场证据**。离线时该按钮变为**保存到本设备**；联网后使用**立即发送**发送。

## 状态含义
- **油轮：适用 / 不适用 / 船舶类型未知：需要审查：**船舶类型未知时，结果保持**需要审查**；绝不会被假定为不适用。
- **等待审查 / 已接受 / 已拒绝：**导入状态。
- **新增 / 已更改 / 未更改 / 不在此次导入中：**与上一次已接受的导入相比的条目状态。不在此次导入中的条目为**保留（从不删除）**。
- **负面观察 / 正面观察 / 无观察 / 未知：**条目上的观察。
- **未关闭 / 未经核验：**此处的发现项始终显示为未关闭且未经核验。
- **未关联措施 / 已关联措施：**发现项是否关联到安全措施。已关联措施并不表示发现项已核验或措施有效。
- **在线采集 / 离线采集：**证据的采集方式。

## 不能做的事 / 注意
- 准备导入的人不能审查它：“您准备了此导入；必须由其他人审查。”
- 本页不关闭也不核验发现项。已核验不等于有效；有效性是针对措施的单独人工审查。
- 在运营方启用经扫描的视频文件类型之前，视频证据不可用。
- 后续导入中缺少的条目绝不会被删除；历史会被保留。

## 出现问题时
- **请求被拒绝：**解决其下方列出的原因。
- **记录已在此期间更改。请重新加载并再次审查。**按**重新加载**。
- **结果未知（连接中断）。**使用**重试同一请求**。
- **您无权读取行业保证记录。**或**您无权执行此操作。**检查您的角色和船舶上下文；必要时联系租户管理员（13.03 §10）。
- 如果证据无法核验，请检查文件 ID、修订版本和 SHA-256 校验和；必要时联系核验人（13.03 §10）。
